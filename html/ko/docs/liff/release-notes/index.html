릴리스 노트

LIFF 버전 및 출시일

LIFF v2.2.0부터 LIFF는 Semantic Versioning(SemVer)을 따릅니다. 자세한 내용은 LIFF 버전 관리 정책을 참조하세요.

CDN 경로

CDN 경로는 고정 경로(fixed)와 에지 경로(edge) 두 가지를 제공합니다. CDN 에지 경로를 사용하면 항상 최신 MINOR 및 PATCH 업데이트가 적용됩니다. CDN 고정 경로를 사용하는 경우에는 업데이트할 때마다 URL을 직접 변경해야 합니다.

자세한 내용은 LIFF 버전 관리 정책 문서의 LIFF SDK(sdk.js) 업데이트 정책을 참조하세요.

현재 버전

CDN 에지 경로(https://static.line-scdn.net/liff/edge/2/sdk.js)를 사용하면 언제나 LIFF v2의 최신 기능을 사용할 수 있습니다.

LIFF v2.31.2: 2026년 10월 7일

버전 목록

CDN 고정 경로(예: https://static.line-scdn.net/liff/edge/versions/2.31.2/sdk.js)를 사용하면 지정한 LIFF 버전의 기능을 사용할 수 있습니다.

2026/10/07

LIFF v2.31.2 출시

LIFF v2.31.2를 출시했습니다.

LIFF v2.31.2에서는 다음과 같이 변경되었습니다.

LIFF URL 쿼리 파라미터 값의 ? 문자 처리 방식을 변경했습니다

2026년 8월 31일에 안내한 것처럼, LIFF URL에 포함된 쿼리 파라미터 값의 ? 문자 처리 방식을 변경했습니다.

사용자가 LIFF URL에 접속하면 LIFF 앱은 먼저 기본 리디렉션 URL로 이동한 다음 보조 리디렉션 URL로 이동합니다. LIFF v2.31.2에서는 LIFF 브라우저에서 LIFF URL의 쿼리 파라미터 값을 보조 리디렉션 URL에 복원하는 처리 방식을 변경했습니다. 아래 예시와 같이 쿼리 파라미터 값의 ? 문자가 더 이상 &로 바뀌지 않습니다.

이 변경은 LIFF 앱이 LIFF 브라우저에서 열릴 때 적용됩니다. 외부 브라우저에서 LIFF 앱을 열 때의 동작은 변경되지 않았습니다.

예시

예를 들어 LIFF 앱의 엔드포인트 URL이 https://example.com이고 사용자가 https://liff.line.me/{liffId}/?key=foo?bar에 접속한다고 가정하겠습니다. 보조 리디렉션 URL은 다음과 같습니다.

변경 전(LIFF v2.31.1 이하) 변경 후(LIFF v2.31.2 이상)
https://example.com?key=foo&bar https://example.com?key=foo?bar

쿼리 파라미터 값의 ? 문자를 퍼센트 인코딩한 https://liff.line.me/{liffId}/?key=foo%3Fbar와 같은 LIFF URL에 접속하는 경우에도 접속 방법에 따라 LIFF 앱이 영향을 받을 수 있습니다. LIFF 브라우저에서 LIFF 앱을 여는 방법별 동작은 다음과 같습니다.

접속 방법 변경 전(LIFF v2.31.1 이하) 변경 후(LIFF v2.31.2 이상)
iOS 기기에서 LINE 앱 이외의 앱으로 접속 https://example.com?key=foo&bar https://example.com?key=foo?bar
iOS 기기에서 LINE 앱으로 접속 https://example.com?key=foo%3Fbar 변경 없음
Android 기기 https://example.com?key=foo%3Fbar 변경 없음

사양 변경에 관한 참고 사항

LIFF 앱이 값으로 URL을 갖는 쿼리 파라미터를 사용하는 경우(예: return_url에 사용자가 이동해 온 페이지의 URL이 포함된 경우), LIFF 브라우저에서 열릴 때 이 변경의 영향을 받을 수 있습니다. 쿼리 파라미터 값을 퍼센트 인코딩하더라도 LIFF URL에 접속하는 방법에 따라 LIFF 앱이 영향을 받을 수 있습니다.

LIFF SDK를 v2.31.2로 업데이트할 때는 변경 후에도 LIFF 앱이 올바르게 동작하는지 확인하세요.

LIFF v2.31.2로 업데이트하는 방법

필요한 작업은 LIFF SDK를 어떤 방식으로 통합했는지에 따라 다릅니다.

  • CDN 에지 경로를 사용하는 경우
  • CDN 고정 경로를 사용하는 경우
  • npm 패키지를 사용하는 경우

CDN 에지 경로를 사용하는 경우

CDN 에지 경로를 사용하는 경우 자동으로 v2.31.2로 업데이트되었습니다. 추가 작업은 필요하지 않습니다.

<script charset="utf-8" src="https://static.line-scdn.net/liff/edge/2/sdk.js"></script>

CDN 고정 경로를 사용하는 경우

CDN 고정 경로를 사용하는 경우 로드하는 버전을 v2.31.2로 변경하세요.

<script charset="utf-8" src="https://static.line-scdn.net/liff/edge/versions/2.31.2/sdk.js"></script>

npm 패키지를 사용하는 경우

npm 패키지를 사용하는 경우 @line/liff를 v2.31.2로 업데이트하세요.

# npm의 경우
npm install @line/liff@2.31.2

# yarn의 경우
yarn add @line/liff@2.31.2

LIFF SDK 통합에 대한 자세한 내용은 LIFF 문서의 LIFF 앱에 LIFF SDK 통합하기를 참조하세요.

컨텍스트 토큰이란 무엇인가요?

컨텍스트 토큰은 LIFF 앱이 실행된 환경에 대한 정보(예: 화면 크기, 사용자 ID)를 담고 있으며, liff.getContext() 메서드로 가져올 수 있습니다. LIFF 앱을 초기화하면(liff.init() 메서드를 실행하면) 브라우저의 localStorage에 context 키로 저장됩니다.

LIFF 앱을 초기화할 때(liff.init()을 실행할 때) 이전 세션에서 생성된 액세스 토큰의 만료 여부를 확인하고, 만료되었다면 컨텍스트 토큰을 폐기합니다. 하지만 LIFF v2.9.1 이하에서는 이 만료 확인이 LIFF 앱 초기화의 마지막 부분에서 이루어졌기 때문에, 폐기되지 않은 이전 토큰이 초기화 중에 참조되어 의도하지 않은 동작이 발생했습니다.

LIFF v2.10.0에서는 액세스 토큰 만료 확인이 LIFF 앱 초기화의 맨 처음에 이루어지므로, 이전 컨텍스트 토큰이 폐기된 후에 초기화가 진행됩니다.

컨텍스트 토큰은 액세스 토큰이 만료되면 폐기됩니다. LIFF v2.10.0에서도 액세스 토큰이 만료되지 않은 동안에는 liff.getContext() 메서드로 가져올 수 있는 컨텍스트 정보가 변경되지 않습니다. 따라서 liff.getContext() 메서드로 가져온 정보가 항상 최신이라고 보장할 수 없습니다.
